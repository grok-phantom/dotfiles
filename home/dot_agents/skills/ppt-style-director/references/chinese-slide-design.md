# 中文 PPT 设计

中文 PPT 不能直接套英文 deck 的版式习惯。中文是方块字，信息密度高，没有天然
词间空格，远看更容易形成一整块灰墙。做中文 deck 时，要额外控制标题、正文密度、
中英混排和数字层级。

## 中文标题

规则：

- 标题写判断，不写栏目名。
- 优先 12-22 个汉字表达核心判断；超过两行要重写。
- 按语义断行，不按视觉长度硬断。
- 避免连续抽象名词堆叠。
- 不要整页都用粗体。标题可以粗，副标题和注释要降级。

好方向：

- “三段式 policy loop 让失败变得可解释”
- “把研发可用推进到展示可信”
- “Production 不是终点，而是稳定性的证明”

坏方向：

- “架构概览”
- “能力升级”
- “智能化闭环体系建设”

## 中文正文密度

规则：

- 中文正文超过 3 行，优先拆成图解、流程、分组、注释或 appendix。
- 每个信息块只表达一个动作或判断。
- 避免把段落直接塞进卡片。
- 页面里如果已经有复杂图，正文必须更短。
- 中文脚注要安静，但来源、口径、版本不能丢。

替代方式：

- 段落 -> 3 步流程；
- 长解释 -> 主图 + 旁注；
- 多个原因 -> 分组标签；
- 大段背景 -> appendix；
- 口号 -> 机制 + 证据。

## 中英混排

中文技术/产品 deck 常有 English term、代码名、指标和数字。它们要有固定层级。

规则：

- 英文术语只在第一次出现时解释，后续保持同一写法。
- 不要随手把英文术语加粗；加粗会让它抢中文标题的层级。
- 数字可以突出，但必须说明单位、口径或状态。
- Code、API、模型名可以用 monospace 或轻微色彩区分，但不要变成装饰。
- 中英混排时，中文判断仍然是主叙事，英文术语服务解释。

示例：

- 好：“Stage Gate 把 Demo、Stage、Production 三个状态区分清楚。”
- 坏：“Stage Gate / Demo / Stage / Production / Reliable / Observable”
  直接堆词，缺少中文判断。

## 数字和数据

规则：

- 数字要对齐，尤其是表格和指标比较。
- 百分比、倍数、时间、金额必须统一格式。
- 红/绿/黄/蓝等语义色必须固定用途，不要每页临时指定。
- 数字如果是结论核心，可以做 hero number；否则不要抢标题。
- 图表标题写结论，不写“数据分析”。

## 中文空泛词

这些词不是绝对禁止，但必须被 proof object 证明：

- 赋能
- 升级
- 打造
- 闭环
- 体系化
- 智能化
- 全链路
- 高质量
- 可持续

替代方式：

- “赋能” -> 说明谁获得什么能力；
- “升级” -> 说明从什么状态到什么状态；
- “闭环” -> 画出输入、处理、反馈、再行动；
- “体系化” -> 展示分层、接口、职责或流程；
- “高质量” -> 给出指标、例子或判定标准。

## 中文页 QA

检查：

- 标题是否是一个具体判断？
- 标题是否超过两行？
- 页面是否出现大段灰墙？
- 中英混排是否有固定层级？
- 英文术语、数字、代码名是否抢中文主叙事？
- 抽象词是否有机制或证据支撑？
- 脚注是否安静但完整？

失败门槛：

- 标题只有栏目名，失败。
- 正文超过 3 行且没有拆解，失败。
- 英文术语堆叠但没有中文判断，失败。
- 使用“赋能/升级/闭环”等词但没有机制或证据，失败。
