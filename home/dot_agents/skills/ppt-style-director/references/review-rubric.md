# Review Rubric

渲染 slide previews 或 contact sheet 后，用这个 rubric 做审美检查。

每项 0-2 分：

- **Claim clarity**：标题是在表达观点，而不只是命名主题。
- **Proof object quality**：页面有真实 evidence、图、工作流、截图、表格或指标。
- **B+D fit**：整体像产品 keynote + 技术清晰度，而不是泛模板。
- **Palette continuity**：全 deck 来自同一套 palette，页面之间不随意跳色。
- **In-slide harmony**：单页配色和谐，强调色有主次和语义。
- **Hierarchy clarity**：标题、主视觉、证据、注释、脚注优先级清楚。
- **Rhythm**：contact sheet 里的页面形态和节奏有变化。
- **Restraint**：没有为了设计而设计；多余装饰、重复文案和无意义图标被删除。
- **Chinese slide fit**：中文标题、正文密度、中英混排、数字层级和空泛词处理得当。
- **Technical truthfulness**：架构页和工作流页语义准确。
- **Readability**：文字、标签、图表、表格在投影距离下可读。
- **Anti-pattern avoidance**：没有 palette 跳变、泛 SaaS 紫色卡片、feature-card
  农场、卡片默认化、图标汤、伪技术复杂感。

## Gates

- 任何单项为 0，最终交付前必须迭代。
- 全 deck 颜色不统一，判定失败；除非换色对应明确章节、语义或接近色过渡。
- 单页配色冲突，判定失败；尤其是强色互相抢层级但没有语义理由。
- 页面第一视觉焦点不明确，判定失败。
- 如果反复出现卡片网格，即使单页干净，也判定 rhythm 失败。
- 如果装饰元素多于证据元素，判定失败。
- 中文 deck 如果标题像口号、正文成灰墙、中英混排抢层级，判定失败。
- 技术 deck 如果图漂亮但语义不准，判定失败。
- 只有抽象主张、没有 proof object 的 deck 判定失败。

## Contact Sheet Questions

检查时问：

- 只看缩略图，能不能看出故事线？
- 只看缩略图，颜色是不是属于同一套系统？
- 页面构图有变化吗，还是都像同一套模板？
- 卡片是否只是局部组织，而不是全 deck 默认版式？
- 一页里最重要的东西是不是一眼能看到？
- 有没有元素只是为了“设计感”而存在？
- 中文页面是否短句化、分组化，而不是大段文字？
- 英文术语和数字是否服务中文主标题，而不是抢走主视觉？
- 有没有至少一个让人记住的 hero object？
- 技术页是不是比白板更冷静、更清楚，而不是更混乱？
- 有没有避开用户已知讨厌的风格？

## Fast Fixes

- 太泛：把卡片网格换成一个 hero object + 一条短 evidence rail。
- 太跳色：回到 deck palette，统一背景系统和强调色。
- 单页太乱：减少强色数量，把语义色固定到状态用途。
- 太卡片：去掉一半外框，改成流程、层级、证据轨或 hero object。
- 层级不清：先确定唯一第一视觉焦点，再重排标题、主视觉、注释。
- 太装饰：删除不承载信息的图标、glow、边框、阴影和重复文案。
- 中文太重：缩短标题，按语义断行，把正文拆成流程、分组、注释或图解。
- 中文太虚：把“赋能/升级/打造/闭环”等词替换成具体机制、动作或结果。
- 太密：拆成一个 claim slide + 一个 appendix/detail slide。
- 太虚：把标题改成判断，并补上缺失机制。
- 太技术：保留真实机制，但增加分组和标签。
