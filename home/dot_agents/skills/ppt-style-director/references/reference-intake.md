# Reference Intake

当用户提供优秀或糟糕的 PPT、截图、网页、keynote、模板、设计作品集或 deck
参考时，用这个流程把感性偏好转成可迁移规则。

目标不是复制参考，而是提取可复用的审美判断。

## 输入要求

用户可以提供：

- PPTX / PDF / 图片 / 截图；
- 网页链接或设计作品链接；
- 一组喜欢的参考和一组讨厌的反例；
- 对某页的口头反馈，例如“颜色跳”“太卡片”“很高级但看不清”。

如果参考很多，优先分析 3-6 个：2 个喜欢、2 个讨厌、1-2 个部分喜欢。

## 分析模板

对每个参考输出：

```text
参考：
喜欢：
不喜欢：

颜色：
- deck palette 是什么？
- 主色、辅助色、语义色如何使用？
- 是否有颜色跳变？如果换色，是否有章节或语义理由？

版式：
- 主要 archetype 是 hero object、流程、架构、数据、对比，还是卡片？
- 为什么这样排？它服务了什么内容？
- 有没有卡片默认化或页面过度规整？

层级：
- 标题、主视觉、证据、注释、脚注的优先级是否清楚？
- 第一视觉焦点是什么？
- 是否有两个元素互相抢注意力？

节奏：
- contact sheet 看是否有变化？
- 变化是否来自内容类型，而不是一页一风格？
- 是否有重复页面结构导致疲劳？

克制：
- 哪些元素体现少即是多？
- 有没有为了设计而设计？
- 哪些元素删掉后页面会更强？

可迁移规则：
- 可以写进 skill 的一句话规则是什么？
- 应该写入 style-directions、anti-patterns 还是 review-rubric？
```

## 写入规则

把结论写入正确文件：

- `style-directions.md`：正向风格原则、页面 archetype、palette、层级、克制原则。
- `anti-patterns.md`：用户讨厌的 visual smell、症状、替代方案。
- `review-rubric.md`：生成后必须检查的打分项、失败门槛、快速修复方式。

写入时使用短规则，不要写长篇欣赏笔记。格式建议：

```text
规则：全 deck 可以有暗色页和浅色页交替，但强调色、字体层级、图形语言必须一致。
来源：用户喜欢的某参考 deck 的章节切换方式。
用途：style-directions.md / 色彩连续性
```

## 判断原则

- 不复制具体视觉皮肤，提取结构规则。
- 不把作品集型夸张设计直接搬进商务/技术 deck。
- 不因为参考好看就接受所有元素；必须指出“不学什么”。
- 用户明确讨厌的东西优先写入 anti-patterns。
- 能阻止未来错误的规则，比描述“它很好看”更有价值。
